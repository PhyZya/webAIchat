# Архитектура

## Общая картина

```
браузер                  наш сервер (Node)              OpenRouter
   │                          │                             │
   │  POST /api/chat          │                             │
   ├─────────────────────────▶│  проверка схемой            │
   │                          │  лимит по адресу            │
   │                          │  + заголовок с ключом       │
   │                          ├────────────────────────────▶│
   │                          │                             │
   │   SSE: delta/done/error  │  разбор потока OpenRouter   │
   │◀─────────────────────────┤◀────────────────────────────┤
   │                          │                             │
   │  закрыл соединение       │  обрывает запрос наверх      │
   ├─────────────────────────▶├────────────────────────────▶│
```

Ключ OpenRouter читается только в `server/src/config.ts` и уходит только
в заголовок исходящего запроса. В клиентском коде нет ни ключа, ни адреса
OpenRouter — браузер знает единственный адрес `/api/chat`.

## Раскладка папок

```
shared/src/     общий код клиента и сервера
  protocol.ts     события потока, коды ошибок, границы размеров
  models.ts       белый список бесплатных моделей
  sse.ts          разбор формата Server-Sent Events

server/src/
  index.ts        поднятие сервера, раздача собранного фронта
  config.ts       переменные окружения, падает при старте без ключа
  constants.ts    таймауты и лимиты, от окружения не зависят
  routes/chat.ts  единственный эндпоинт: проверка входа и перекладывание в SSE
  openrouter/     всё, что знает про OpenRouter
    client.ts       запрос, таймауты, отмена, логирование
    chunk.ts        разбор одного события потока
    errors.ts       перевод отказов в коды протокола
    deadlines.ts    сторож таймаутов
  lib/
    logger.ts       единая обёртка логов
    rate-limit.ts   ограничение частоты по адресу

web/src/
  App.tsx         сборка экрана, клавиатура, прокрутка
  features/chat/  состояние диалога, без разметки
    useChat.ts      отправка, поток, остановка, повтор
    streamClient.ts обращение к /api/chat и чтение потока
    turns.ts        чистые операции над списком реплик
    history.ts      sessionStorage
    errorText.ts    коды ошибок в слова
  components/     разметка и стили, без бизнес-логики
```

## Ключевые решения

**Сервер разбирает поток, а не перекладывает байты.** OpenRouter может ответить
HTTP 200, начать поток и положить отказ в его середину. При простой перекачке
клиент этого не заметит и покажет оборванный ответ как успешный.

**Три таймаута вместо одного.** Ожидание первого токена (30 с), пауза между
токенами (30 с) и потолок на весь ответ (180 с). Один общий таймаут либо рубит
длинный честный ответ, либо не ловит зависший поток.

**Отмена доведена до конца цепочки.** Браузер закрывает соединение → сервер
видит закрытие → обрывает запрос к OpenRouter. Иначе «Стоп» гасит интерфейс,
а генерация продолжает тратить квоту.

**Ограничение частоты запросов.** Спрятать ключ на сервере недостаточно: без
лимита открытый `/api/chat` — это публичный бесплатный доступ к нашей квоте
для любого, кто узнал адрес.

**Белый список моделей.** Клиент присылает идентификатор модели, и без проверки
через наш ключ можно было бы дёрнуть платную.

**Состояние отдельно от разметки.** `features/chat` не знает про DOM,
`components` не знает про сеть.
