# Нить

Веб-чат с языковой моделью через OpenRouter. Ответ приходит потоком, генерацию
можно оборвать на середине, ключ не покидает сервер.

## Запуск за пять минут

Нужен Node 20.19 или новее.

```bash
npm install
cp .env.example .env
```

Откройте `.env` и впишите ключ OpenRouter — взять его можно на
[openrouter.ai/keys](https://openrouter.ai/keys). Файл уже в `.gitignore`.

Включите хук, который не даст закоммитить секрет (одна команда, один раз):

```bash
git config core.hooksPath .githooks
```

```bash
npm run dev
```

Откроется два процесса: прокси на `http://localhost:8787` и интерфейс на
`http://localhost:5173`. Заходить нужно на второй.

Без ключа сервер не стартует и говорит об этом словами — это намеренно:
пусть падает при запуске, а не в первом запросе пользователя.

### Остальные команды

```bash
npm test          # тесты
npm run typecheck # проверка типов
npm run lint      # линтер
npm run build     # сборка фронта в web/dist
npm start         # один процесс: сервер раздаёт собранный фронт
```

## Ключевые решения

### Ключ не попадает в браузер

Читается в одном файле (`server/src/config.ts`) и уходит в один заголовок
(`server/src/openrouter/client.ts`). В клиентском коде нет ни ключа, ни адреса
OpenRouter: браузер знает единственный адрес `/api/chat`. Во вкладке Network
видно только обращения к localhost.

Ключ не попадает и в репозиторий. Защиты три, потому что из истории git секрет
потом не вычистить — только переписыванием всех коммитов:

1. `.env` в `.gitignore`;
2. хук `.githooks/pre-commit` отклоняет коммит, если в нём оказался файл `.env`
   или строка, похожая на ключ OpenRouter, OpenAI или Anthropic;
3. в логи сервера пишутся идентификаторы и размеры, но не тела запросов —
   `server/src/lib/logger.ts` принимает только примитивы, так что передать
   туда переписку или ключ нельзя по типу.

### Сервер разбирает поток, а не перекладывает байты

Самое неочевидное место задания. OpenRouter может ответить `200 OK`, начать
поток и положить отказ **в его середину** — например, при исчерпании лимита.
Прокси, который просто перекачивает байты, отдаст такой ответ как успешный,
и пользователь увидит текст, оборванный без объяснения.

Поэтому сервер разбирает поток OpenRouter и отдаёт вниз свой узкий протокол
из трёх событий: `delta`, `done`, `error` с кодом. Заодно наружу не течёт
ничего лишнего, а тексты ошибок живут на клиенте — сервер словами
не разговаривает.

### Отмена доведена до конца цепочки

«Стоп» в браузере прерывает `fetch` → соединение закрывается → сервер видит
закрытие и обрывает свой запрос к OpenRouter. Если оборвать только на клиенте,
интерфейс замрёт, а генерация продолжит тратить бесплатную квоту.

Уже полученный кусок остаётся в истории и помечается как остановленный — как
и требует задание. То же самое происходит при ошибке посреди потока.

### Обрыв связи ловится с двух сторон

Серверные таймауты не спасают от одного случая: если умирает сам сервер,
отсчитывать их некому, и браузер ждёт вечно. Отличить «сервер думает над
ответом» от «сервера больше нет» по молчанию соединения невозможно.

Поэтому сервер раз в пять секунд пишет в поток SSE-комментарий — по
спецификации читатель его игнорирует, а для нас это признак жизни. Клиент
считает тишину дольше двадцати секунд обрывом связи.

### Таймаутов три, а не один

| Что сторожим | Сколько ждём |
|---|---|
| первый токен | 30 с |
| пауза между токенами | 30 с |
| весь ответ целиком | 180 с |

Один общий таймаут пришлось бы ставить либо коротким — и он рубил бы длинные
честные ответы, либо длинным — и тогда зависший на середине поток висел бы
минутами. Отдельный сторож ожидания старта нужен потому, что бесплатные модели
часто встают в очередь и не начинают отвечать вовсе.

### История переживает перезагрузку, но не переживает вкладку

Выбран `sessionStorage`. Задание формулирует требование как «история в рамках
сессии» — `sessionStorage` буквально это и есть: случайное обновление страницы
диалог не теряет, а закрытие вкладки стирает.

`localStorage` хранил бы переписку бессрочно в чужом браузере без явного
согласия — для чата с моделью, куда люди вставляют рабочие тексты, это плохой
дефолт. Незавершённые ответы не восстанавливаются: оборванный поток после
перезагрузки всё равно не продолжить, и показывать вечное «думает» нечестно.

Каждый ответ хранит идентификатор своей модели. Поэтому смена модели в шапке
или перезагрузка страницы не переписывают подписи старых реплик.

### Селектор моделей — не украшение

Бесплатные модели регулярно заняты и отвечают 429. Это не теория: во время
проверки две модели из четырёх отдавали отказ подряд, и порядок в списке
пришлось поменять так, чтобы первой шла отвечающая — встречать человека
ошибкой на первом же сообщении плохо. Возможность перейти на соседнюю модель
превращает тупик в действие.

Список моделей — белый и живёт на сервере: без него клиент мог бы через наш
ключ дёрнуть платную модель.

### Markdown в ответах — и почему это вопрос безопасности

Ответ модели — недоверенные данные. В них может оказаться и разметка,
и ссылка куда угодно, поэтому вставлять их в страницу через `innerHTML`
нельзя ни при каких условиях.

`react-markdown` подключён без `rehype-raw`: сырой HTML из ответа не
выполняется, а показывается текстом. Проверено — подложенные в ответ
`<script>`, `<img onerror>` и ссылка вида `javascript:` не сработали:
скрипт не выполнился, картинка не создалась, адрес ссылки очистился.
Внешние ссылки открываются с `rel="noopener noreferrer nofollow"`.

Разметка разбирается на каждый новый кусок текста, то есть заведомо
неполной — с незакрытым блоком кода или оборванной таблицей. Это нормально:
показывается то, что уже пришло, остальное достраивается по мере поступления.

Цена бонуса честная: собранный клиент вырос с 73 до 120 КБ в сжатом виде —
`react-markdown` тянет за собой разбор и преобразование разметки. Для чата,
где ответы регулярно содержат списки, таблицы и код, обмен выглядит
оправданным; если бы вес был критичен, разумнее взять разборщик полегче.

### «Нить» — индикатор, а не декор

Вертикальная линия слева от ответа — это конечный автомат состояний потока:
пунктир с рябью, пока ждём первый токен; сплошная с бегущей искрой, пока идёт
текст; остывшая, когда модель договорила; оборванная с расплетёнными
волокнами, если нажали «Стоп»; красная оборванная при ошибке.

Она закрывает три требования сразу: показать, что модель печатает; показать,
что ответ неполный; не оставлять человека наедине с вечным спиннером.
Для программы чтения с экрана линия скрыта — то же самое сказано словами.

## Что я сделал иначе, чем просили, и почему

Задание просит отмечать такие места, поэтому вот они.

### 1. Обводку фокуса убрал, но взамен нарисовал свою

**Требование:** «Уберите стандартную браузерную обводку фокуса (`outline`)
у кнопок и поля ввода».

**Что не так:** оно противоречит соседнему требованию из того же задания —
«интерфейсом можно полноценно пользоваться с клавиатуры». Голый
`outline: none` — самый известный способ сломать клавиатурную навигацию:
Tab продолжает работать, но человек перестаёт видеть, где находится.

**Что сделал:** браузерную обводку погасил — она действительно выглядит
по-разному в разных браузерах и портит вид. Вместо неё рисую собственное
кольцо на `:focus-visible` (`web/src/styles/global.css`). При щелчке мышью его
нет, при переходе по Tab — есть, выглядит одинаково везде. Вместо `outline: none`
стоит прозрачная обводка: в режиме высокой контрастности Windows тени не
рисуются, и только она оставляет фокус видимым. Требование
выполнено по сути (аккуратный единообразный вид), нарушено по букве.

### 2. Добавил ограничение частоты запросов, хотя об этом не просили

Требование «ключ не должен попадать в браузер» закрывает утечку ключа, но
не закрывает то, что эндпоинт `/api/chat` открыт любому, кто узнал адрес.
Без лимита это публичный бесплатный доступ к чужой квоте — то есть половина
решения. Добавил простой счётчик по адресу клиента.

### 3. Enter отправляет, но перенос строки нужен

Задание требует «Enter отправляет». Тогда в поле нельзя сделать абзац.
Сделал стандартное разделение: `Enter` — отправить, `Shift+Enter` — перенос.
`Esc` слушаю на всём окне, а не на кнопке «Стоп»: иначе сочетание работало бы
только когда фокус уже стоит на этой кнопке, то есть практически никогда.

### 4. Тёмная тема не сделана

Названа в задании бонусом. Сознательно не брал, чтобы не делать наспех:
это второй проход по всем цветам и проверка контраста заново. Палитра уже
вынесена в токены, так что работа предсказуемая — просто не в этот заход.

## Тесты

Профиль проекта — MVP, поэтому покрытие не сплошное, а точечное: 20 тестов
на те места, где ошибка тихая и дорогая.

* `shared/src/sse.test.ts` — разбор потока: событие, разорванное между кусками
  сети; keep-alive комментарии OpenRouter; CRLF.
* `server/src/openrouter/chunk.test.ts` — разбор события, в том числе главный
  случай: отказ, приехавший в середине уже открытого потока; закрытие потока без
  `[DONE]` и `finish_reason`.
* `server/src/lib/rate-limit.test.ts` — исчерпание и восстановление лимита.
* `web/src/features/chat/chat.smoke.test.tsx` — главный сценарий: ответ приходит
  частями, останавливается, сохраняется и после перезагрузки показывается
  с исходной моделью.
* `web/src/features/chat/turns.test.ts` — повтор выбранного ответа и то, что
  длинная история укладывается в границы сервера.
* `web/src/features/chat/streamClient.test.ts` — завершение чтения по итоговому
  событию.

Чего тестами не покрыто и проверялось руками — с результатами:

| Сценарий | Как проверялся | Что получилось |
|---|---|---|
| Потоковый вывод | живой запрос к модели | текст приходит кусками, в логе `chars: 23, ms: 1928` |
| Остановка по Esc | прерывание на середине | сохранено 1001 знак, статус `stopped`, интерфейс живой |
| Отмена доходит до OpenRouter | обрыв соединения, чтение лога | `outcome: "cancelled"`, запрос наверх прекращён |
| Ошибка 429 | бесплатная модель была занята | «Модель сейчас занята», подсказка подождать 5 секунд из `Retry-After` |
| Обрыв связи | сервер убит посреди генерации | через 20 секунд «Нет связи с сервером» и кнопка повтора |
| Ключ в браузере | вкладка Network | 165 запросов, все на localhost, к openrouter.ai — ни одного |
| История после перезагрузки | F5 | диалог на месте, незавершённые ответы не восстанавливаются |
| Клавиатура | Tab, Enter, Shift+Enter, Esc | обход работает, фокус видно на каждом шаге |
| Узкий экран | эмуляция 375 px | горизонтальной прокрутки нет, широкая таблица прокручивается внутри блока |
| Разметка в ответе | запрос с заголовком, списком, таблицей, кодом и цитатой | всё отрисовано |
| Опасный ответ модели | в ответ подложены `<script>`, `<img onerror>` и ссылка `javascript:` | ничего не выполнилось, HTML показан текстом |

Таймауты модели (30 секунд до первого токена, 30 на паузу в потоке)
проверены только кодом: вызвать их на живой модели надёжным образом
не получилось.

реализацию, я перечитывал и правил. Ниже — честный список мест, где модель

Главный урок последней строки: большую правку от ИИ нельзя принимать целиком,
даже если тесты зелёные. Тесты не заметили бы пропажу README и комментариев —
это видно только глазами в диффе.

Отдельно: модель охотно предлагает «не падать» там, где падать нужно —
проглотить ошибку, вернуть пустой массив, подставить заглушку. Такие места
приходится ловить глазами; в этом проекте пустые `catch` остались только там,
где рядом написано, почему пусто.
