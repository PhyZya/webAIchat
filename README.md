# Нить

Веб-чат с языковой моделью через OpenRouter. Ответ приходит потоком, генерацию
можно оборвать на середине, ключ не покидает сервер.

## Запуск за пять минут

Нужен Node 20.19 или новее.

```bash
npm install
cp .env.example .env
```

Откройте `.env` и впишите ключ OpenRouter — взять его можно на
[openrouter.ai/keys](https://openrouter.ai/keys). Файл уже в `.gitignore`.

```bash
npm run dev
```

Откроется два процесса: прокси на `http://localhost:8787` и интерфейс на
`http://localhost:5173`. Заходить нужно на второй.

Без ключа сервер не стартует и говорит об этом словами — это намеренно:
пусть падает при запуске, а не в первом запросе пользователя.

### Остальные команды

```bash
npm test          # тесты
npm run typecheck # проверка типов
npm run lint      # линтер
npm run build     # сборка фронта в web/dist
npm start         # один процесс: сервер раздаёт собранный фронт
```

## Ключевые решения

### Ключ не попадает в браузер

Читается в одном файле (`server/src/config.ts`) и уходит в один заголовок
(`server/src/openrouter/client.ts`). В клиентском коде нет ни ключа, ни адреса
OpenRouter: браузер знает единственный адрес `/api/chat`. Во вкладке Network
видно только обращения к localhost.

### Сервер разбирает поток, а не перекладывает байты

Самое неочевидное место задания. OpenRouter может ответить `200 OK`, начать
поток и положить отказ **в его середину** — например, при исчерпании лимита.
Прокси, который просто перекачивает байты, отдаст такой ответ как успешный,
и пользователь увидит текст, оборванный без объяснения.

Поэтому сервер разбирает поток OpenRouter и отдаёт вниз свой узкий протокол
из трёх событий: `delta`, `done`, `error` с кодом. Заодно наружу не течёт
ничего лишнего, а тексты ошибок живут на клиенте — сервер словами
не разговаривает.

### Отмена доведена до конца цепочки

«Стоп» в браузере прерывает `fetch` → соединение закрывается → сервер видит
закрытие и обрывает свой запрос к OpenRouter. Если оборвать только на клиенте,
интерфейс замрёт, а генерация продолжит тратить бесплатную квоту.

Уже полученный кусок остаётся в истории и помечается как остановленный — как
и требует задание. То же самое происходит при ошибке посреди потока.

### Таймаутов три, а не один

| Что сторожим | Сколько ждём |
|---|---|
| первый токен | 30 с |
| пауза между токенами | 30 с |
| весь ответ целиком | 180 с |

Один общий таймаут пришлось бы ставить либо коротким — и он рубил бы длинные
честные ответы, либо длинным — и тогда зависший на середине поток висел бы
минутами. Отдельный сторож ожидания старта нужен потому, что бесплатные модели
часто встают в очередь и не начинают отвечать вовсе.

### История переживает перезагрузку, но не переживает вкладку

Выбран `sessionStorage`. Задание формулирует требование как «история в рамках
сессии» — `sessionStorage` буквально это и есть: случайное обновление страницы
диалог не теряет, а закрытие вкладки стирает.

`localStorage` хранил бы переписку бессрочно в чужом браузере без явного
согласия — для чата с моделью, куда люди вставляют рабочие тексты, это плохой
дефолт. Незавершённые ответы не восстанавливаются: оборванный поток после
перезагрузки всё равно не продолжить, и показывать вечное «думает» нечестно.

### Селектор моделей — не украшение

Бесплатные модели регулярно заняты и отвечают 429. Возможность перейти
на соседнюю превращает тупик в действие. Список моделей — белый, на сервере:
без него клиент мог бы через наш ключ дёрнуть платную модель.

### «Нить» — индикатор, а не декор

Вертикальная линия слева от ответа — это конечный автомат состояний потока:
пунктир с рябью, пока ждём первый токен; сплошная с бегущей искрой, пока идёт
текст; остывшая, когда модель договорила; оборванная с расплетёнными
волокнами, если нажали «Стоп»; красная оборванная при ошибке.

Она закрывает три требования сразу: показать, что модель печатает; показать,
что ответ неполный; не оставлять человека наедине с вечным спиннером.
Для программы чтения с экрана линия скрыта — то же самое сказано словами.

## Что я сделал иначе, чем просили, и почему

Задание просит отмечать такие места, поэтому вот они.

### 1. Обводку фокуса убрал, но взамен нарисовал свою

**Требование:** «Уберите стандартную браузерную обводку фокуса (`outline`)
у кнопок и поля ввода».

**Что не так:** оно противоречит соседнему требованию из того же задания —
«интерфейсом можно полноценно пользоваться с клавиатуры». Голый
`outline: none` — самый известный способ сломать клавиатурную навигацию:
Tab продолжает работать, но человек перестаёт видеть, где находится.

**Что сделал:** браузерную обводку погасил — она действительно выглядит
по-разному в разных браузерах и портит вид. Вместо неё рисую собственное
кольцо на `:focus-visible` (`web/src/styles/global.css`). При щелчке мышью его
нет, при переходе по Tab — есть, выглядит одинаково везде. Требование
выполнено по сути (аккуратный единообразный вид), нарушено по букве.

### 2. Добавил ограничение частоты запросов, хотя об этом не просили

Требование «ключ не должен попадать в браузер» закрывает утечку ключа, но
не закрывает то, что эндпоинт `/api/chat` открыт любому, кто узнал адрес.
Без лимита это публичный бесплатный доступ к чужой квоте — то есть половина
решения. Добавил простой счётчик по адресу клиента.

### 3. Enter отправляет, но перенос строки нужен

Задание требует «Enter отправляет». Тогда в поле нельзя сделать абзац.
Сделал стандартное разделение: `Enter` — отправить, `Shift+Enter` — перенос.
`Esc` слушаю на всём окне, а не на кнопке «Стоп»: иначе сочетание работало бы
только когда фокус уже стоит на этой кнопке, то есть практически никогда.

### 4. Markdown и тёмная тема не сделаны

Оба названы в задании бонусами. Сознательно не брал, чтобы уложиться
в отведённое время и не делать их наспех: потоковый markdown требует
аккуратной обработки незакрытых блоков кода, а тема — второго прохода
по всем цветам. Что было бы дальше — ниже.

## Тесты

Профиль проекта — MVP, поэтому покрытие не сплошное, а точечное: 13 тестов
на те места, где ошибка тихая и дорогая.

* `shared/src/sse.test.ts` — разбор потока: событие, разорванное между кусками
  сети; keep-alive комментарии OpenRouter; CRLF.
* `server/src/openrouter/chunk.test.ts` — разбор события, в том числе главный
  случай: отказ, приехавший в середине уже открытого потока.
* `server/src/lib/rate-limit.test.ts` — исчерпание и восстановление лимита.

Чего тестами не покрыто и проверялось руками: сам сетевой обмен, поведение
интерфейса при остановке, вёрстка на узком экране.
